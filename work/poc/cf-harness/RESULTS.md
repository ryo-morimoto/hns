# 計測結果

2026-11-07。pi-durable 1.5.0 + `cf dev`（ローカル workerd）と、`cf deploy` した実デプロイの両方。
台本は 1 ターン = bash → write → read → 完了。**1 ターン 4 op。**

## 実測

| 経路 | ターン p50 | RPC p50 | RPC p95 | op / ターン |
| --- | --- | --- | --- | --- |
| 直接（localhost） | 106ms | 5ms | 11ms | 3.8 |
| 人工遅延 25ms | 209ms | 30ms | 34ms | 4.0 |
| 人工遅延 50ms | 313ms | 57ms | 60ms | 4.0 |
| ローカル workerd + 実エッジ（cloudflared） | 231ms | 29ms | 61ms | 3.9 |
| **実デプロイ（workers.dev + cloudflared）** | **181ms** | **28ms** | **61ms** | **3.9** |

実デプロイの内訳（15 ターン / 59 op）:

| op | 回数 | 平均 |
| --- | --- | --- |
| write | 15 | 32ms |
| stat | 15 | 27ms |
| read | 15 | 17ms |
| bash | 14 | 53ms |

## 読み方

- **1 op あたり 30ms 前後、p95 で 60ms。** 見積もり（25〜60ms）どおり。
- ターン ≈ 100ms + op数 × RTT。4 op で 180ms。
- ローカル workerd + トンネル（231ms）より**実デプロイの方が速い**（181ms）。
  DO が colo 内でエッジに着くため。事前の予想どおり。
- モデルの応答（秒）に比べれば 1〜3 割。20 op のターンなら 1.2s 前後。

## eviction と復帰

15 ターン後に 75 秒待って再開した。

- `GET /api/state` は **98ms** で応答（DO インスタンスは作り直され、metrics は 0 に戻った）
- `conversationId` は `ctx.storage` から**復元された**（会話は DO SQLite に残っている）
- 復帰後の最初の write は ~180ms、以降は通常値。以降のターンも継続して成功

つまり「プロセスが消えても会話と状態は戻る」は、この範囲では確認できた。
