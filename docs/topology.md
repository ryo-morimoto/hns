# マシン側の責務の分解

「各マシンで何が要るか」を分けて、案を比べる。A = 中央 + pi-env（SSH）、A' = 中央 + 常駐 Agent、B = 各マシン Durable。

| # | 責務 | 中身 | A | A' | B | MVP |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 接続 | 中央からマシンへ届くか | SSH（到達性が要る） | 外向き接続 | 外向き接続 | ○ |
| 2 | 認証 | 誰がそのマシンで動かせるか | SSH 鍵・ホスト鍵 | Agent トークン | 同左 | ○ |
| 3 | セットアップ | root 作成・clone・worktree | exec で可（前提は人手） | Agent が recipes を実行 | 同左 | ○ |
| 4 | 資格情報 | git / gh / Model 鍵 | マシンに事前設定（転送なし） | Agent が保持・注入 | ローカル | ○ |
| 5 | ツールチェーン | node, rust, nix 等 | 既存前提 | 導入も可 | 既存前提 | △ |
| 6 | 常駐サービス | dev server, LSP | ×（セッション用） | ○ 監督 | ○ | — |
| 7 | ポート | プレビュー URL | × 転送なし | ○ | ○ | — |
| 8 | インフラ | VM・コンテナの起動/停止 | 別問題 | 別問題 | 別問題 | — |
| 9 | データ所在 | 会話・履歴 | 中央 | 中央 | マシン | — |
| 10 | 運用 | 版・更新・障害 | 1版 | 1版 + Agent 配布 | N版 + Agent 配布 | — |

「—」は今回の範囲外。残る差は 1〜4 と、6・7（常駐・ポート）だけ。

6 の根拠: [daemon-life](../work/poc/daemon-life/)（切断後にデーモンは死に、開始したプロセスは残った）。

## 分解して分かったこと

- **1〜4 はどの案でも「コマンドを実行する」だけ**。pi-env の exec で足りる。差は「誰が前提を用意するか」。
- **6・7 は A では無理**。ただし MVP（会話→編集→差分→再開）には要らない。
- **8 はどの案でも解決しない**（インフラの起動は別レイヤー）。
- **10 は A が最も軽い**（1プロセス・1版）。

## 決定: まず A（D004）

前提を明示して A で進める。

- 対象マシンは tailnet などで**到達できる**（この環境は tailnet 上）。
- マシンは開発済みで、**git / gh / tooling は既に認証・導入済み**（個人の開発マシン）。
- **常駐サービスとプレビューは対象外**。`sudo` や対話ログインは人手。

## A' に上げる条件

- 新しいマシンの初期化（clone・鍵・ツール導入）をプロダクトの機能にする。
- 資格情報をプロダクトが管理する。
- dev server の常駐・プレビューが要る。

## B に上げる条件

- 要件#2 を「各マシンで Agent ループが動く」と厳密に解釈する。
- 中央に会話・鍵を置けない（オフライン・分断・データ所在地）。

## 移行コスト

`ExecutionEnv` が境界なので、A → A' は輸送層（SSH → 外向き接続）の差し替え、A' → B はループの配置換え。
どちらも Workspace と Tool の実装は再利用できる。
