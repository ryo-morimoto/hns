# 配置: Core Agent をどこで動かすか

要件#2「複数マシンで Core Agent を動かせる」の解釈。**未決（BOARD D-2）**。

## 案

| 案 | ループ | Tool の実行 | 実装 |
| --- | --- | --- | --- |
| **A** 中央 + 遠隔 | 中央の Durable 1つ | 対象マシンの SSH daemon（pi-env） | 小 |
| **B** 各マシン | 各マシンの Durable | そのマシンのローカル FS | 大 |

共通の境界は `ExecutionEnv`。A は会話ごとに `RemoteExecutionEnv` を返し、B は各マシンが同じ Tool をローカル env で動かす。

## 比較

| 観点 | A | B |
| --- | --- | --- |
| 要件#2 の文言適合 | △（Agent は中央。Tool だけ実機） | ○ |
| 複数マシンの同時操作（#3） | ○ 1つの会話から切替 | ○ ただし Run の集約が要る |
| マシン停止時 | その Workspace だけ失敗 | そのマシンの Run だけ失敗 |
| Tool のレイテンシ | SSH 往復（LAN 数ms、WAN 数十ms） | ローカル（最速） |
| 資格情報 | 中央に SSH 鍵と Model 鍵 | 各マシンに Model 鍵（または proxy） |
| 通信の向き | 中央 → マシン（到達性が必要） | マシン → 中央（NAT 内で可） |
| データ | ファイルはマシン、会話は中央 | 両方マシン。UI への投影が必要 |
| 運用 | 1プロセス・1版 | N プロセス・版ずれ・更新配布 |
| 復旧 | 中央の Storage 1つ | マシンごとの Storage 集約 |
| 実装 | 小（env builder + daemon 配置） | 大（常駐・接続・配布） |

## 事実

- Durable の `env` は**会話ごとに差し替え可能**: `HarnessOptions.env(target: { conversationId, cwd, read })`。
  つまり A でも会話ごとに別マシンを割り当てられる（[実測](../work/research/pi-durable-1.5.0.md)）。
- `RemoteExecutionEnv` は適合テスト 29/29。SSH はホスト鍵確認・転送なし・デーモンは SHA-256 検証付きで配置。
- Durable の Storage は**書き込みが1プロセス前提**（他は `readOnly` で開く）。A はこれに合う。

## 推奨

**A を実装し、B は `ExecutionEnv` 境界を保って保留する。**

- 要件#3（1UI から全マシン）と #4（会話）は A で最短に成立する。
- 要件#2 は「Tool が実機で動く」と解釈すれば満たすが、**文言通りに Core Agent を各マシンで動かすなら B**。
- 境界が共通なので、M3 の比較試験（T-05）まで B を実装しない。

## B に切り替える条件

- マシンが NAT 内にあり、中央から SSH で到達できない（→ B は外向き接続のみで済む）。
- Model 鍵を各マシンに置けない / 中央に集めたくない。
- 分断・オフラインでも Agent を動かす必要がある。
- 遠隔 Tool の往復が実用に耐えないと測れた。
