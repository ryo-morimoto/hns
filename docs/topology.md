# 配置: Core Agent とマシン側の実行主体

要件#2「複数マシンで Core Agent を動かせる」と、各マシンのワークスペース準備をどう担うか。**未決（BOARD D-2）**。

## pi-env の限界（実測）

pi-env は「セッション中に SSH 越しでファイルとコマンドを触る」層で、マシンを管理する主体ではない。

- **SSH 前提**: 中央から各マシンへ到達できること、SSH サーバ・鍵・ホスト鍵承認が必要。NAT 内は不可。
- **転送なし**: `sshArguments` は "no forwarding of any kind"。git / gh の認証は各マシンに事前設定が必要。
- **一般ユーザー権限**: sudo・システムパッケージの導入は非対話では不可。
- **セッション用**: 接続が切れるとデーモンは落ち、開始したプロセスの後始末は保証されない。
  実測ではデーモンは死に、背景プロセスは残った（[daemon-life](../work/poc/daemon-life/)）。
- **ポート転送なし**: dev server のプレビューを外に出せない。

→ **pi-env だけでは「ワークスペースのセットアップ」をプロダクト機能にできない。**

## 案

| 案 | ループ | マシン側 | セットアップ |
| --- | --- | --- | --- |
| A | 中央 Durable | pi-env（SSH、セッション） | 都度の exec。前提は人手 |
| **A'** | 中央 Durable | **常駐 Machine Agent**（外向き接続） | Agent が実行・監督 |
| B | 各マシンの Durable | ローカル env | そのマシンの Agent が実行 |

A' は pi-env のデーモンとプロトコルを Agent の内部に再利用し、外向き接続・常駐・サービス監督を被せる。

## 推奨

**A' を実装し、B は M3 まで保留。**

- 要件#3（1UI から全マシン）と #4（会話）は中央ループで最短に成立する。
- セットアップとサービスは Agent に閉じ込めれば、中央は「実行環境」としてだけ扱える。
- 要件#2 を文言通りに満たす必要が出たら、同じ Agent に Durable を載せて B にする（Agent は共通）。

## B に切り替える条件

- 要件#2 を「各マシンで Agent ループが動く」と厳密に解釈する。
- 中央に会話・鍵を置けない（オフライン・分断・データ所在地の制約）。
- 遠隔 Tool の往復が実用に耐えないと測れた。
