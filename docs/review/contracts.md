# 契約と互換の観点

wire・公開 signature・イベント名・保存形式・互換が変わる変更で読む。根拠は [design.md](../design.md)。

| 観点               | 条件                                                                                | 確認                                                                                        | Ref                                                                                                                                                                                                                                                           |
| ------------------ | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入口を片方だけ塞ぐ | 同じ値が複数の入口（body / query / path params / header / 内部 API）から来る        | 入口を列挙し、規則の無い入口から危険な値を通す。規則は1箇所に共有する                       | [Parse, Don't Validate](https://lexi-lambda.github.io/blog/2019/11/05/parse-don-t-validate/), [DRY](https://pragprog.com/titles/tpp20/the-pragmatic-programmer-20th-anniversary-edition/)                                                                     |
| 表現が2つある      | wire と内部で型が違う（クエリ文字列、0/1、ISO 以外）。base64 など長さを宣言する応答 | 実クエリ・実レスポンスを parse に通す。長さ・ハッシュを照合し、切れた応答が黙って読めないか | [Least Astonishment](https://www.infoq.com/articles/API-Design-Joshua-Bloch/), [Illegal States](https://fsharpforfunandprofit.com/series/designing-with-types/), [Parse, Don't Validate](https://lexi-lambda.github.io/blog/2019/11/05/parse-don-t-validate/) |
| 互換を黙って壊す   | 公開 signature・wire のキー・イベント名・ファイル API の意味が変わる                | 利用者（他パッケージ・PoC・保存済み Journal/DB）を列挙し、移行か decisions の記録を求める   | [API Design](https://www.infoq.com/articles/API-Design-Joshua-Bloch/), [Rust API Guidelines](https://rust-lang.github.io/api-guidelines/), [Hyrum's Law](https://www.hyrumslaw.com/), [AIP-158](https://google.aip.dev/158)                                   |
